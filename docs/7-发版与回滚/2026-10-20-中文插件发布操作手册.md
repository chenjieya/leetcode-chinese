## 2. GitHub 发布

1. 默认分支应包含准确的 manifest.json、README.md、LICENSE 和源码。
2. 本地运行 pnpm lint、pnpm test、pnpm build、pnpm run check:bundle-size。
3. manifest.json、package.json 与发布标签版本一致，例如 1.0.0；Obsidian 标签使用 x.y.z，不加 v 前缀。
4. 推送标签后，GitHub Actions 再次检查、构建并创建 Release。
5. Release 需包含独立附件 main.js、manifest.json、styles.css；额外提供 leetcode-chinese.zip 供手动安装。
6. 在 GitHub Actions 和 Releases 页面确认任务成功及附件齐全后再提交市场。

中文独立版生产包约 1.95 MB。体积检查以现有依赖和中国站适配为基线：超过 1,980,000 字节预警，超过 2,000,000 字节阻止发布；没有关闭体积门禁。

日常开发使用 pnpm 10.28.0 和已提交的 pnpm-lock.yaml。自动发布不读取开发机 data.json，不应上传 Cookie、AI 密钥、个人配置和日志。

## 3. 新版市场手动提交

截至核对时，新流程在 [Obsidian Community](https://community.obsidian.md) 网站完成，不是修改旧 community-plugins.json 列表。

1. 登录 Obsidian 账号。
2. 在个人资料页面连接 GitHub，授权验证 chenjieya 的仓库所有权。
3. 进入 Plugins，选择 New plugin。
4. GitHub repository URL 填写 https://github.com/chenjieya/leetcode-chinese，Owner 选择自己的账号。
5. 核对从默认分支读取的插件标识、名称、描述和版本。
6. 阅读开发者政策与持续维护声明；只确认符合真实情况的条款，再提交。
7. 查看自动检查反馈；需要修复时修改代码、递增版本、创建新 Release，再按页面指引发布。

建议说明：

> LeetCode Chinese 是基于 Mo Xu / moxu 的 obsidian-leetcode 开发的中文衍生版本，面向力扣中国站，适配中国站账号、题库、运行与提交，并提供中文笔记、AI 复盘和模式索引。项目保留 MIT 许可证及原作者贡献说明。

### 3.1 衍生插件政策状态

新版市场仍保留 Forks 条款：通常要求原作者公开可核验的书面同意；另一条路径要求能证明作者无法联系且项目至少六个月无更新，之后联系并给予三十天回应期。

本项目当前没有提供原作者同意上架的证明，也没有核验完成另一条路径的全部条件。应如实说明衍生关系，不把 MIT 授权、切换中国站或新建仓库描述为市场特殊批准。维护者应在提交前处理这一条件，或通过官方支持咨询适用情况。GitHub 发布与社区市场收录是独立状态。

## 4. 测试与升级

开发机的旧测试路径曾使用 .obsidian/plugins/leetcode 联接到本仓库。插件 ID 已更改，新版本应安装到 .obsidian/plugins/leetcode-chinese，不能仅在旧插件目录替换 manifest.json 后继续使用。

新插件的设置与备份位于独立目录，不自动复制旧插件的凭据。选择已有题目目录后，会复用题目笔记并兼容原来的属性与代码围栏；请关闭原插件后测试。

需要回滚时，关闭插件，从上一版 Release 恢复三个插件文件，保留 data.json 和题目笔记。首次从原插件迁移前，建议备份笔记库；目录迁移与新增笔记内容不随插件文件回滚自动撤销。
